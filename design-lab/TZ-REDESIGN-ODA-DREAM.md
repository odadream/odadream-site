## 1. Контекст и источники

Сайт перестраивается из художественного текстового пространства в **навигатор и доказательство для партнёра, пришедшего из письма**. Входных замечаний — четыре:

1. **Личный UX/UI-аудит** текущего `odadream-site` (гл. 2 ниже).
2. **Аутрич-бриф** (файл выше): обозначено ядро позиционирования, IA, шаблоны страниц, страницы сотрудничества, критерий готовности.
3. **Сигнал партнёра:** «сайт очень сложен в навигации».
4. **Ощущение автора:** концепция «цветущего лотоса» как навигации + палитры тайлов художественно симпатична, но неудобна; в мобильном формате панель уходит вниз и не считывается — сайт становится только текстовым. Нужен утилитарный инструмент outreach при сохранении фирменного стиля. Попытка v2 (газетный ретро‑хай‑тек, бумага/типографика) не подошла. Ориентиры: refikanadol.com, fuseworks.it, ouchhh.tv.

### 2.2. Что уже хорошо и должно быть сохранено

- **Контентная модель Lotus** (фронтматтер + bilingual EN/RU + `---RU---`) — зрелая, с 246 проверенных узлов, provenance-данными (`kind`, `proofs`, `orgs`, `issued_by`, `media`), пайплайном реальных изображений (`contentLoader.ts`, `realImageCatalog.ts`). Переписывать контент не нужно — редизайн это **слой представления и маршрутизации**.
- **ProvenancePanel** — готовый компонент показа «доказательств» (media, orgs, venues, proofs, business) под каждый узел; основа для case‑studies и страниц форматов.
- **Медиа-пайплайн** (`data/media.ts`, `realImageCatalog.ts`, `mediaHelpers.ts`) и лёгкие lazy-чанки (`App.tsx:12–20`).
- **Динамический SEO**: `updateMetaTags()` переписывает `og:*` и title на каждый узел (`NavigationContext.tsx:458`); JSON‑LD `PerformingGroup` в `index.html`.
- **Тёмная «tech noir» база** (`theme-color #050505`, JetBrains Mono, `.bg-noise`), 4 готовые темы в CSS (switcher выключен).
- **Сигнатурный визуал**: лотос/SVG-тайлы, бренд «ODA.dream», векторный движок логотипа из v2 (`odadream-site-2/odadream-vector-engine-v2-standalone.html`, без зависимости от шрифтов — переиспользовать как знак/водяной знак).

### 2.3. Технические якоря для исполнителя

- Ленивые панели: `TextPanel`, `LotusGrid`, `Lightbox` (named exports) — при редизайне сохранить `React.lazy`.
- Разбор wiki-ссылок и embed: `transformWikiLinks` / `parseContentAndExtractMedia` в `contentProcessor.ts`.
- Узлы → страницы: `findPathToNode`, `NODE_REGISTRY`, `ROOT_NODE` в `nodeHelpers.ts`, `constants.ts`.
- Статика деплоится на GitHub Pages с `base: './'`; `deploy.yml` без изменений не требуется, кроме 404-редиректа при SPA-роутинге.

## 3. Диагноз: три корневые причины

1. **CSS of «галерея вместо сервиса».** Сайт показывает «каким художником мы были», а не «что мы сделаем для вас». (причины P1, P5, P6)
2. **Абстрактный вход.** Фрактальный лотос — восхитительная карта, но плохой навигатор: пользователь вынужден «гулять по дереву», а не выбирать сценарий. (P2, P3)
3. **Нет pathways и proof layer.** Любая рассылка упирается в «напишите нам», нет явных маршрутов сотрудничества, таблиц форматов, кейсов и media‑kit, и нет URL, куда вести письмо. (P4)

## 4. Концепция новой версии — «Evidence‑first Portal»

**Формула (из брифа, зафиксирована):**
> ODA.dream creates participatory Art & Science experiences that make human attention and connection perceptible.

**Название концепции:** «Signal / Evidence‑first portal» — тёмный кинематографичный портал, где **первым слоем — тела, внимание, пространство и доказательства**, вторым — техника. Лотос остаётся в качестве **фирменного «map»-режима** (вторичная навигация и фирменный знак), а не главного меню.

### 4.1. Визуальный язык (по референсам)

- **refikanadol.com** → полноэкранное иммерсивное видео/постеры, огромная минимальная типографика, навигация — тонкая строка сверху, редкая сетка, «arrow_outward».
- **fuseworks.it** → студийная галерейная сетка, чёткие разделы (Works / Live / Artworks / Exhibitions / Agenda / Studio / Archive), спокойные холст-тоны.
- **ouchhh.tv** → монолитные data‑paintings, лаконичные секции PROJECTS / INFO / NEW MEDIA LAB, «музейное» ощущение.

Вывод для системы:
- База: глубокий тёмный фон `#050505–#0b0b0e`, лёгкое зерно (`.bg-noise` уже есть).
- Свет: единственный «сияющий» акцент (электроминтальный/янтарный — финализировать открытым вопросом Q1), используется редко и точечно: активный пункт, live-индикатор, фокус, hover.
- Типографика: без «газетного» ультра‑гротеска. Держать **2 лица**: широкий нейтральный гротеск для заголовков (Space Grotesk / Archivo) + JetBrains Mono для данных/этикеток/номеров (моно уже в проекте). Строгая табличная сетка, мелкие индексные номера разделов (`01 / Works`), тонкие правила.
- Медиа: 16:9 video с **аффишным постером и загрузкой по действию** (никакого тяжёлого autoplay на всех страницах); подписи «работа — год — контекст» обязательны.
- Логотип: переиспользовать SVG‑контуры из v2 без бумажного фона — «signature» на тёмном, в виде водяного знака и в футере; буквенная марка `ODA.dream`.
- Motion: медленный, детерминированный, соответствующий манере: crossfade разделов, просветление постеров, тонкая параллаксная волна; без «циферблатов» и без кардиограмм как декора.

### 4.2. Информационная архитектура + URL‑карта

Две языковые версии RU/EN равноправны, язык в пути (`/en/…`, `/ru/…`), переключение без потери страницы. Ядро — из брифа §4:

```text
/                                   Главная (формула + 3 входа + 1 доказательство + next-step)
/works                              Работы (индекс из hub-works)
/works/:slug                        Landing работы — ГЛУБОКАЯ ССЫЛКА ДЛЯ ПИСЕМ
/formats                            Готовые форматы событий (таблица Neurobattle / MindShow / лекция)
/cooperation/institutions           Фестивали, институции, университеты
/cooperation/brands                 Бренды, агентства, конференции
/cooperation/immersive              Immersive-пространства и спонсорские активации
/cooperation/wellness               Отели и wellness (Атлас состояний)
/studio                             Практика и технология + Этика и согласие
/cases                              Кейсы, отклики, пресса
/materials                          Media-kit: профиль, биографии, 1-страничные PDF, техрайдер
/contacts                           Контактная форма с выбором намерения
/<node-slug>                        Универсальная страница любого узла (fallback, не ломая Lotus)

```

Маппинг на существующие node‑графы: `/works` → `hub-works`; `/works/:slug` → любой узел `kind: product`/`type: content` из работ (маршрут из `hub-works`); `/cooperation/*` → разделы `hub-collab`; `/cases` → `hub-events` + `proofs` + `hub-business`; `/studio` → `hub-tech` + `hub-cv` + биографии; `/materials` → служебная страница. **Фрактальный лотос/`map` публикуется как режим «Explore map»** внутри `/works` и как футер-виджет.

### 4.3. Принципы навигации

Desktop:
- Постоянный верхний омлет-бар: `ODA.dream` + разделы (Works, Formats, Cooperation ▾, Studio, Cases) + `Contact` (всегда виден) + RU/EN + «Explore map».
- Первичный путь для письма — карточки/таблицы и CTA, не дерево.

Mobile:
- Фиксированный верх с маркой и бургером; **постоянная нижняя навигация c подписями** (Works · Formats · Project · Contact) — читаемая, с акцентом активного раздела.
- Видео/постер/факты и CTA — **выше** длинного текста.
- Лотос/карта — опциональный горизонтальный «map»-виджер внутри работ, не обязательный первичный навигатор.

## 5. Карта экранов и шаблонов

### 5.1. Главная (HomePage)
1. Hero: постер/видео живого действия (60–90 с, poster + play по действию). Формула + 2 кнопки: «Посмотреть работы», «Найти формат сотрудничества».
2. Три входа (карточки): «Готовые живые форматы» / «Новые работы с локальным сообществом» / «Долгие пространственные опыты» — по одной фразе и ссылке.
3. Одна сильная доказательная работа — «Интерференции реальностей» (12 + 12 в ЭЭГ, ИКЦ Калуга): 40–60 c video + 4 факта + версии (премьерная/облегчённая).
4. Как из взаимодействия возникает форма — 4 шага без техпаспорта.
5. Реальные контексты и партнёры (только осуществлённые; без «стены логотипов» и без намёка, что несостоявшиеся контакты = партнёры).
6. Next-step: 3 CTA («Обсудить событие» / «Обсудить комиссию» / «Обсудить пилот») → `/contacts?intent=…`.

### 5.2. Landing работы (`/works/:slug`) — шаблон №1
Заголовок, год, статус (`реализовано/в развитии/концепт для комиссии`) → 1 предложение переживания участника → 60–90 c video на первом экране → контекст и художественная ставка → «как устроено участие» → «как возникает форма» → документация (фото высокого качества, короткая версия, полное видео по запросу) → факты (место/дата/участники/команда/партнёры/технологии — только проверяемые) → версии (существующая/компактная/новая локальная) → соразмерный CTA. Источник данных — узел + `ProvenancePanel` + `data/media.ts`.

### 5.3. Форматы (`/formats`) — шаблон №2 (самая сканируемая страница)
Таблица: Формат | Что происходит | Пропускная способность | Подходит для (+ видео 20–30 c, фото, площадь/экран/электропитание, команда, что остаётся заказчику). CTA: «Получить краткий media kit», «Прислать бриф». Публикуемые диапазоны вместо цен.

### 5.4. Маршруты сотрудничества (`/cooperation/*`)
Общий скелет: кому → обещание → дискретные видео/фото → процесс (римскими шагами) → роли и что требуется от принимающей стороны → типовой таймлайн → CTA («Запросить concept note», «Обсудить пилот»). Для brands — таблица форматов; для immersive — блок «Production footprint»; для wellness — путь fit-сессия → пилот → оценка → программа. **Запрещено** «привезём готовую инсталляцию» в секции институций.

### 5.5. Studio / Materials / Cases / Contacts
- `/studio`: принцип (связь важнее показателя), рабочие источники, real-time-преобразование, опыт коллективной системы (12×12-матрица на примере постановки), раздел «Этика и согласие», меню и техно-дата без перегруза.
- `/cases`: 4–6 кейсов «задача/формат/масштаб/результат», отзывы с именем+родью+разрешением публикации, логотипы только фактических партнёров, пресса со ссылками.
- `/materials`: профиль, биографии Ольги и Далера, общий 1-стр. PDF, PDF по направлениям, трейлер 84 c, лого/фото для прессы/техрайдер, `hi@odadream.art`. PDF дополняет страницы, не заменяет их.
- `/contacts`: **одна форма, выбор намерения** (событие/бренд · комиссия · immersive/спонсор · wellness-пилот · пресса/исследование/другое) → релевантные 3–5 полей → email/telegram дублируются в футере.

## 6. Требования к реализации (LLM-исполнителю)

### 6.1. Стек и зависимости
- Остаться: Vite 5 + React 18 + TS strict + Tailwind; контент — `.md` через `buildUnifiedGraph`; GitHub Pages с `base:'./'`.
- Добавить маршрутизатор: **`react-router-dom`** (v6). По умолчанию **`HashRouter`** (мгновенно работает на статике GH Pages без серверных правил; no‑refresh-потери). Опционально потом: `BrowserRouter` + `404.html` SPA-редирект — выносится в отдельный шаг (Q2).
- НЕ добавлять тяжёлые UI-фреймворки; не вводить компонентные библиотеки — только Tailwind утилиты и разумные локальные примитивы.

### 6.2. Роутинг и маппинг
- Новый модуль `src/router.tsx`: таблица маршрутов и `nodeId → path` resolver (slugs: транслитерация/биллингва id или чистые `id` из фронтматтера). `?internal=true&id=` и `?id=` продолжать работать → редирект на новый URL.
- `lang` в пути: `/:lang/:route`; дефолт по `oda_lang`/`navigator.language`; переключение сохраняет страницу.
- Fallback-роут `<NodeSlugPage>` открывает любой узел (title/desc/медиа/provenance) — **гарантия, что ничего из 246 файлов не потеряется**; неизвестный slug → 404.
- Учесть перезагрузку/освежение на статике (HashRouter решает) и «обратные ссылки из текста» (`contentProcessor` генерирует `?internal=true&id=`; заменить на ссылки роутера при переходе, сохранив fallback).

### 6.3. Компоненты и файлы
- `src/pages/` — `HomePage`, `WorksIndex`, `WorkLanding`, `Formats`, `Cooperation`, `Studio`, `Cases`, `Materials`, `Contacts`, `NodeSlug`, `NotFound`.
- `src/components/` — переиспользовать `TextPanel` (рендер), `Lightbox`, `ProvenancePanel`, `HeaderTabs` (переписать в маршрутизированный верх/низ), `LotusGrid` (обернуть в «map»-mode). Вынести новые: `WorkCard`, `FormatTable`, `RouteCard`, `ContactForm`, `LangSwitch`, `Breadcrumbs`, `PosterVideo`.
- `src/styles/` — `theme.ts` расширить токенами: `--accent`, `--surface`, `--ink`, новые layout-классы; старые class-«пути» сохранить как алиасы.
- `index.html` — оставить meta/OG/JSON‑LD; добавить `404`-обработку для SPA (шаг опционален); сохранить текущие viewport-фиксы.

### 6.4. Контентный пайплайн (запреты и правила)
- **НЕ переписывать** `.md`-файлы, не менять схему фронтматтера, не запускать `npm run registry:sync` (регенерирует стабы и может затереть ворк доступ). Редактировать контент только точечно и по явному запросу.
- Использовать существующие хелперы: `buildUnifiedGraph`, `findPathToNode`, `transformWikiLinks`, `MEDIA`, `REAL_IMAGE_CATALOG`, `ProvenancePanel`.
- Новые «служебные» страницы (Materials, Formats, Cooperation) — сначала **написать в контент-терминах** (bilingual frontmatter), потом рендерить шаблоном, чтобы kept source-of-truth = один контент-слой.

### 6.5. Конверсия и контакты
- Форма `/contacts` — клиентская с выбором намерения; отправка — настраиваемым бэкендом (Formspree/Web3Forms/telegram-бот; решить Q3). На случай отсутствия — `mailto:hi@odadream.art`.
- Единый публичный контакт: `hi@odadream.art` + Telegram; email обязан быть реальным и обслуженным.

### 6.6. Производительность и a11y
- Постеры вместо автоплэя; видео грузится по действию; lazy-чанки страниц.
- Бюджеты: initial JS ≤ 200 kB gzip (остаётся lazy), первая отрисовка мобильного ≥ 60 Lighthouse, все CTA и навигация — фокусопный, контраст ≥ WCAG AA, `prefers-reduced-motion` отключает параллакс.
- Никакого autoplay sound; все видео с подписями RU/EN и подписью «что зритель видит».

### 6.7. Ограничения и запреты
- Не использовать шрифты с загрузкой из внешних CDN как обязательные (Google Fonts допустимо только с `display=swap` и fallback).
- Не рисовать «медицинский» язык, «диагностика», обещания эффекта (из брифа §2.4).
- Не публиковать цены; только производственные диапазоны/масштабы.
- Не смешивать реализованные работы, референсы и гипотезы — у каждого объекта честный статус.

## 10. Открытые вопросы (решения по умолчанию)

- **Q1 — акцентный цвет.** По умолчанию: «свет» = тёплый янтарь/шафран на чёрном (уникален и близок к лотосу); альтернатива — электроминтальный (ближе к нейро). Решается автором на стадии визуальной системы.
- **Q2 — URL-стратегия.** По умолчанию HashRouter (сразу работает на GH Pages). Миграция на BrowserRouter+404.html — отдельный низкоприоритетный шаг.
- **Q3 — бэкенд формы.** По умолчанию — `mailto` на первом этапе; Formspree/Telegram-бот как отдельная задача.
- **Q4 — судьба лотоса.** По умолчанию: map-режим внутри `/works` и футер-виджет; полное удаление — не рекомендуется (фирменный знак и часть аудitorium-идентичности).
