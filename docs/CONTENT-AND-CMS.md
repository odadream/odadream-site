# Контент, модель данных и CMS

## Что работает сейчас

V2 — статический многостраничный сайт на Astro. Контент собирается в HTML во время сборки; браузеру не нужны запросы к базе данных для открытия работы или события. Редакторской панели и пользовательского CRUD-интерфейса сейчас нет.

Основной набор записей находится в `src/data/site.ts` как типизированные TypeScript-массивы:

| Тип записи     | Содержание и связи                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------- |
| `Work`         | Работа, RU/EN-тексты, статусы, медиа, события и конфигурации показа                                   |
| `WorkConfiguration` | Конфигурация с обязательным workId, участием, параметрами и распределением ответственности                                               |
| `Programme` | Лекция, практикум или учебная лаборатория: аудитория, содержание, результат, авторы, условия, источники, Work/Case/Media |
| `CaseEvent`    | Событие с датой, местом, ролью ODA.dream, связью с работой, организациями, доказательствами и медиа |
| `Evidence`     | Источник вида `event-record`, `document` или `press`, ссылка на первичную запись и разрешение       |
| `Recognition`  | Награда, сертификат или письмо: вид, организация, год, источник, публикационный статус и права      |
| `Organization` | Организация и её тип роли                                                                           |
| `Person`       | Люди, роли и источники                                                                              |
| `Media`        | Путь к локальному файлу, RU/EN alt и подпись, источник, права и тип медиа                           |
| `WorkDocument` | Архивный PDF конкретной работы: язык, год, страницы, размер, права, историческое пояснение и внутренний хеш |
| `HeroVisual`   | Кураторская последовательность медиумов hero; ссылки на `Media` хранятся ID, не копиями путей       |
| `SocialLink`   | Проверенный URL и доступность канала по языкам                                                      |

Страницы генерируются из маршрутов в `src/lib/routes.ts` и шаблона `src/components/PageView.astro`. Карточки работ — компоненты интерфейса; они читают записи из массива `works`, а не являются отдельными CMS-файлами.

`case-details.ts` сохраняет четыре подробных кейса и три исходных кратких контекста; `additional-events.ts` дополняет их остальным корпусом. Сейчас 33 CaseEvent и четыре EventSeries. `CaseEvent` хранит точность и смысл даты, интервал события, статус участия, публичный/частный/лабораторный/заявочный контекст, связь Work/Method/Programme, дополнительные связи, роли, ограничения, медиа и sourceRefs. Work/Programme получают обратные связи из этих записей. Series объединяет издания; её `updated` не становится датой нового события. Публичная проекция фильтрует зависимости и убирает внутренние источники. `CaseRow` выводит метаданные над рассказом, материалы и переходы; подробная страница создаётся по достаточности рассказа.

`evidence-details.ts` связывает Evidence с конкретным поддерживаемым утверждением, а Recognition — с адресатом, содержанием документа, пределами подтверждения и состоянием скана. Для четырёх доступных изображений зафиксирован SHA-256 просмотренного файла; МФТИ явно остаётся записью без скана. Проверка содержания документа не меняет documentRights или publication. В публичной проекции нет sourceRefs и documentSha256. Связи с отложенными работами/контекстами скрываются. Разрешённый оригинальный URL документа входит в allowlist только для доступного документа; release gate дополнительно проверяет физическое присутствие файла, а не только разрешённый путь.

Содержательные детали девяти выбранных Work находятся в `src/data/work-details.ts` и присоединяются к тем же каноническим записям по ID: `story` (смысловые разделы RU/EN), `credits` (имя и конкретная роль), `reviewNotes` (границы интерпретации для читателя), `relatedWorks` и внутренние `sourceRefs`. Карточка получает только краткие поля; рассказ отображает общий EditorialSections, без текстовых веток по ID в шаблоне. Отложенные связанные работы исключаются из публичных ссылок. SHA-256 не входят в публичную проекцию.

`src/data/studio.ts` содержит модуль Studio и двух отдельных Person с краткими биографиями. Studio связывает людей, художественную позицию, три образовательных контекста с точностью до года и доступные HTML-материалы. Приглашение не означает постоянного преподавания или партнёрства; даты-заглушки не становятся точными днями. Публикация Studio зависит от публикации указанных людей. Регалии, архивные показатели CV и грантовые утверждения не считаются подтверждёнными этим переносом. Файловый presskit не создан: архивные PDF о других проектах не выдаются за актуальную презентацию выбранного пакета.

`publication` и `rights/permission` — поля контроля публикации, а не возможности редактирования. `npm run release:check` запрещает выпуск при неутверждённом контенте или правах. Внутренняя карта 238 старых ID в `src/data/legacy-map.json` служит учётом источников и не входит в публичную сборку; старые Markdown-файлы служили источником выборки, но не работают как CMS нового сайта.

## Ограничения текущего слоя

- Для изменения текста или связи нужно редактировать TypeScript, затем собирать сайт.
- Структурированные типы для работ, конфигураций и образовательных программ, кейсов, свидетельств, признаний, людей, организаций, медиа, hero-материалов и соцсетей есть. Это пока TypeScript-данные, не редакторская форма.
- Подтверждения связаны с кейсами как `Evidence`, но текущий набор записей состоит главным образом из записей о событиях; полный архив признаний ещё переносится.
- Вехи главной теперь производятся из записей кейсов; текущие четыре кейса — проверяемое ядро, не полный перенос событийного реестра.
- Соцсети хранятся в `socialLinks`; официальный профиль VK не подтверждён, поэтому не подменён ссылкой на отдельный пост.
- Пять записей прежнего публичного архива признаний перенесены в тип `Recognition`; четыре выбранные записи показаны на главной и в архиве. Три найденных скана имеют кликабельные локальные превью, скан МФТИ по прежнему пути отсутствует. Все права на повторную публикацию остаются `review`, поэтому release gate закрыт.
- В `Work` используются отдельные `stage`, `workType`, `aliases`, `basedOn`, `components`, `year`, `edition` и `featuredOnHome`. Стадия: концепция, прототип, в производстве, реализовано. Доступность/репертуар хранятся отдельно.
- `HeroVisual` хранит ID медиа и типизированную цель (`Work` с опциональным `CaseEvent` либо `unmapped`), а не копии заголовка/подзаголовка. Для `unmapped` показывается причина отсутствия ссылки; release gate требует связать каждый кадр до выпуска.
- Сейчас в каталоге 23 работы (13 реализованных, 10 концептов/прототипов), две конфигурации работ, восемь программ и семь кейсов. На главной — шесть избранных реализованных работ. Это кураторское ядро, не полный перенос старого корпуса.
- Для hero подготовлены пять локальных веб-фрагментов и постеров из пользовательских источников. Исходники остаются вне репозитория; владелец разрешил показ выбранных медиа 2026-10-05 (`rights: cleared`). Прототип с Еленой Ковылиной исключён из hero главной. Шестой указанный ролик пока не найден.

## Что унаследовано

- Выборочные тексты и факты из старого двуязычного Markdown-корпуса; у записей сохранены `legacyId` и ссылки на исходники.
- Маршрутизация старых `?id=` через явную карту соответствий; основной старый React/Lotus-граф и все его карточки в движок V2 не переносились.
- Часть брендовых файлов и семь выбранных локальных изображений. Показ выбранных изображений, включая частные заказы, разрешён владельцем 2026-10-05; разрешение зафиксировано в CONTENT-AND-CMS.md.
- Утверждённый визуальный язык V5: палитра, роли шрифтов и принципы компонентов сведены к токенам V2. Технические решения синхронизации описаны в `DESIGN-SYSTEM-SOURCE.md`.

Новый сайт не наследует базу старого сайта: граф Lotus не является его источником данных во время сборки.

## Golem Data Base и MindDB

Прямого клиента/API-связи с Golem Data Base или MindDB в браузере нет. Команда `npm run stats:golem -- <path-to-event_registry.json>` готовит обезличенный агрегат из read-only реестра. Текущий снимок Golem от 2026-08-31 содержит 55 папок событий: 30 со связанными источниками, 13 с неоднозначными связями и 12 изолированных. Это единица архивной инвентаризации, не количество подтверждённых публичных показов. Семь курируемых кейсов V2 считаются отдельно, с разбивкой по типу.

Для hero подготовлен локальный агрегированный снимок MindDB на 2026-08-30 из каталога сессий и QC-проверки длительности: 150 сессий, 1 751 тейк, длительность измерена для 1 348 видео и суммирована примерно в 69,8 часа. В сайт не переносились строки отдельных тейков, участники или исходные отчёты.

Это редакционный снимок, а не живая интеграция; `publication` и `privacyReview` остаются `review`. PUBLICATION-SCOPE-01 реализован: агрегат отложен в publication-plan.ts и отсутствует в публичном блоке и данных. Если он включён в пакет, gate требует оба одобрения; простое отключение проверки при оставшемся показе не допускается. Распределение тета/альфа/бета/гамма не рассчитано по утверждённой методике и не отображается как данные. Для будущего обновления нужны владелец источника, повторяемый экспорт, определения метрик, проверка согласий и приватности, дата актуальности и поведение при устаревшем снимке. Браузер не подключается к частной базе.

## Рекомендуемое развитие CMS

Следующий небольшой шаг — вынести карточки из `site.ts` в отдельные проверяемые файлы данных (например, Astro Content Collections с общей схемой), оставив рендеринг статическим. Это улучшит редактирование и ревью, не добавляя серверную базу.

Графические связи и ссылки на provenance останутся явными ID-ссылками и будут проверяться при сборке. Вопрос о веб-панели решать отдельно: она нужна только если определены редакторы, права, согласование и удобный процесс хранения изменений в Git. Не подключать Golem как CMS без подтверждения, что он должен быть источником публичного контента.

Источник: прямое сообщение владельца в рабочей задаче Codex. Эти уточнения имеют приоритет над прежними редакционными предположениями и статусами старого сайта.

- «Эмомандала» — одна составная работа: концепт эмоционального интеллекта, приложение для поиска внутреннего отклика, нарратив пользователя, физический артефакт, ончейн-сайт, связанный с нарративом и историей создания. Метод Эмомандала OS остаётся связанной технологией. Конкретный публичный URL ончейн-паспорта пока не указан.
- «Круг синхронизации» — концепт отдельной инсталляции на основе работы «Нейросинхронизация». Связь Work.basedOn явная; страницы обеих работ связаны в обе стороны.

Это разрешение показа не заменяет отдельные решения о доступности заказа, публикации персональных исходников MindDB, фактах признаний или судьбе исторических URL.

## Общие правила выборки и проверок

`src/data/site.ts` хранит редакционный корпус. `src/data/publication-plan.ts` фиксирует версию и явные ID кандидатов первого пакета; наличие ID не изменяет publication. `src/lib/publication-scope.ts` проверяет выбранные записи, разрешения и зависимости, ограничивает поля публичной проекции и собирает allowlist файлов. `src/data/catalogue.ts` предоставляет одинаковую выборку для компонентов, маршрутов, статистики и gate. Подробные внутренние локаторы остаются в редакционном корпусе; в публичной проекции source содержит только URL, остальные локаторы убираются. Стадия не определяет доступность заказа.

`npm run dev` показывает весь редакционный каталог с заметкой предпросмотра и noindex, включая ещё не принятые документы и статистику. Это локальная рабочая среда; её нельзя использовать как публичный хостинг. Дизайн-стенд подключается только в dev из `src/views/DesignSystem.astro`. `npm run build` формирует только публичную проекцию: неопубликованные Work/Case не создают HTML/routes/sitemap, документы и MindDB отключаются целиком, физические файлы public/ проходят allowlist. `scripts/verify-build.mjs` проверяет и фактическое отсутствие исключённых файлов, и отсутствие внутренних локаторов в HTML/JSON/JS. Старый `?id`, прежний `/formats/` и неизвестная страница используют общий `LegacyNotice`: предупреждение, ручная ссылка и переход на главную соответствующего языка через пять секунд. Публичной таблицы соответствий ID нет; внутренний resolver остаётся инструментом учёта источников, а не маршрутизацией сайта.

Скрипты читают доверенные TypeScript-модули через scripts/site-data.mjs; build сверяет канонические пути с routes.ts без фиксированного числа страниц. content:check проверяет редакционный корпус. Release gate проверяет выбранный пакет, зависимости, права и конфигурацию аналитики; build проверяет физический allowlist и отсутствие внутренних локаторов. В текущем артефакте 88 канонических локализованных страниц и два noindex-входа /formats/, подготовленные Work доступны. Полнота миграции не выводится из успешной сборки или release gate: остаются полный корпус, медиа и итоговые проверки. Старые URL сняты с условий выпуска решением владельца 2026-10-07.


## Метод, условия участия и сотрудничество — актуально 2026-10-07

`src/data/editorial.ts` содержит типизированные Method, детали участия, CooperationPage и 109 точных снимков источников. `src/data/site.ts` объединяет их с базовым корпусом. Условия параметров участия имеют состояния historical/per-brief/conflict; длительность раунда, сессии, аудитория, одновременно измеряемые участники и поток посетителей не смешиваются. Явные конфликты таймингов сохраняются до редакционного уточнения. Источники и хеши внутренние; публичная проекция не содержит sourceRefs.

HeroVisual.target допускает Work или Method; источник изображения не получает выдуманное название работы ради ссылки. Publication plan включает метод и Cooperation как отдельные разрешённые модули; отдельные права медиа остаются обязательными. Registry маршрутов содержит реальные якоря канонических страниц; старый ID теперь показывает общий экран смены структуры, а не выбирает публичный раздел. content:check проверяет вложенные RU/EN-поля, связи, состояния параметров и соответствие снимков существующему inventory.

Процент миграции вычисляется из взвешенных завершённых результатов в существующем backlog командой `npm run migration:status`. Он отделён от публикационного gate, финальной редактуры и качества дизайна.

`audit:media` теперь инвентаризирует всю архивную public-папку в существующем `docs/media-audit.json`, включая PDF/M4V. Хеш и наличие редакционной копии отделены от фактического попадания в разрешённый публичный пакет. Процедурные Lotus-узлы и служебные файлы имеют отдельный учёт; 198 содержательных файлов входят в очередь отбора для нового сайта; сохранение их прежних путей не обязательно. Итог записывается в `currentResourceAudit` существующего inventory, без нового файла описания миграции. content/build проверяют SHA-256 подготовленных файлов и физический allowlist; чтение скана и запись в allowlist не заменяют права или физический файл.
