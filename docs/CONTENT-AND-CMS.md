# Контент, модель данных и CMS

Действующий контракт полей/публикации и интеграций. Статусы и счётчики исполнения — только PROJECT-BACKLOG.yaml и `npm run task`; дизайн компонентов — DESIGN-GUIDE.md. Протоколы прошлых этапов доступны в Git 71c3218. Новые отчёты проверок сюда не дописываются.

## Что работает сейчас

V2 — статический многостраничный сайт на Astro. Контент собирается в HTML во время сборки; браузеру не нужны запросы к базе данных для открытия работы или события. Редакторской панели и пользовательского CRUD-интерфейса сейчас нет.

Основной набор записей находится в `src/data/site.ts` как типизированные TypeScript-массивы:

| Тип записи     | Содержание и связи                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------- |
| `Work`         | Работа, RU/EN-тексты, статусы, медиа, события и конфигурации показа                                   |
| `WorkConfiguration` | Конфигурация с обязательным workId, участием, параметрами и распределением ответственности                                               |
| `Programme` | Лекция, практикум или учебная лаборатория: аудитория, содержание, результат, авторы, условия, источники, Work/Case/Media |
| `CaseEvent`    | Событие с датой, местом, ролью ODA.dream, связью с работой, организациями, доказательствами и медиа |
| `Evidence`     | Источник вида `event-record`, `document` или `press`, ссылка на первичную запись и разрешение       |
| `Recognition`  | Награда, сертификат, письмо, грант или результат отбора: вид, организация, год, предел подтверждения, состояние скана и права      |
| `Organization` | Организация и её тип роли                                                                           |
| `Person`       | Люди, роли и источники                                                                              |
| `Media`        | Путь к локальному файлу, RU/EN alt и подпись, источник, права и тип медиа                           |
| `WorkDocument` | Документ работы: исходный PDF, страницы WebP, язык, год, размеры, права, историческое пояснение и внутренний хеш |
| `HeroVisual`   | Кураторская последовательность медиумов hero; ссылки на `Media` хранятся ID, не копиями путей       |
| `SocialLink`   | Проверенный URL и доступность канала по языкам                                                      |

Страницы генерируются из маршрутов в `src/lib/routes.ts` и шаблона `src/components/PageView.astro`. Карточки работ — компоненты интерфейса; они читают записи из массива `works`, а не являются отдельными CMS-файлами.

`case-details.ts` сохраняет четыре подробных кейса и три исходных кратких контекста; `additional-events.ts` дополняет их остальным корпусом. Сейчас 43 CaseEvent и четыре EventSeries. `CaseEvent` хранит точность и смысл даты, интервал события, статус участия, публичный/частный/лабораторный/заявочный контекст, связь Work/Method/Programme, дополнительные связи, роли, ограничения, медиа и sourceRefs. Work/Programme получают обратные связи из этих записей. Series объединяет издания; её `updated` не становится датой нового события. Публичная проекция фильтрует зависимости и убирает внутренние источники. `CaseRow` выводит метаданные над рассказом, материалы и переходы; подробная страница создаётся по достаточности рассказа.

`evidence-details.ts` связывает Evidence с конкретным поддерживаемым утверждением, а Recognition — с адресатом, содержанием документа, пределами подтверждения и состоянием скана. Сейчас 17 Recognition: 13 сканов и четыре записи без скана (МФТИ и три квалифицированных результата). Для доступных изображений зафиксированы SHA-256 просмотренных файлов. Проверка содержания документа не меняет documentRights или publication. В публичной проекции нет sourceRefs и documentSha256. Связи с отложенными работами/контекстами скрываются. Разрешённый оригинальный URL документа входит в allowlist только для доступного документа; release gate дополнительно проверяет физическое присутствие файла, а не только разрешённый путь.

Содержательные детали девяти выбранных Work находятся в `src/data/work-details.ts` и присоединяются к тем же каноническим записям по ID: `story` (смысловые разделы RU/EN), `credits` (имя и конкретная роль), `reviewNotes` (границы интерпретации для читателя), `relatedWorks` и внутренние `sourceRefs`. Карточка получает только краткие поля; рассказ отображает общий EditorialSections, без текстовых веток по ID в шаблоне. Отложенные связанные работы исключаются из публичных ссылок. SHA-256 не входят в публичную проекцию.

`src/data/studio.ts` содержит модуль Studio и двух отдельных Person с краткими биографиями. Studio связывает людей, художественную позицию, три образовательных контекста с точностью до года и доступные HTML-материалы. Приглашение не означает постоянного преподавания или партнёрства; даты-заглушки не становятся точными днями. Публикация Studio зависит от публикации указанных людей. Регалии, архивные показатели CV и грантовые утверждения не считаются подтверждёнными этим переносом. Файловый presskit не создан: архивные PDF о других проектах не выдаются за актуальную презентацию выбранного пакета.

`publication` и `rights/permission` — поля контроля публикации, а не возможности редактирования. `npm run release:check` запрещает выпуск при неутверждённом контенте или правах. Внутренняя карта 238 старых ID в `src/data/legacy-map.json` служит учётом источников и не входит в публичную сборку; старые Markdown-файлы служили источником выборки, но не работают как CMS нового сайта.

## Ограничения текущего слоя

- Для изменения текста или связи нужно редактировать TypeScript, затем собирать сайт.
- Структурированные типы для работ, конфигураций и образовательных программ, кейсов, свидетельств, признаний, людей, организаций, медиа, hero-материалов и соцсетей есть. Это пока TypeScript-данные, не редакторская форма.
- Подтверждения связаны с кейсами как `Evidence`, но текущий набор записей состоит главным образом из записей о событиях; архив признаний перенесён отдельно в Recognition с подтверждаемым фактом и состоянием документа.
- Вехи главной теперь производятся из записей кейсов; исходные четыре подробных кейса — проверяемое ядро, не полный перенос событийного реестра.
- Соцсети хранятся в `socialLinks`; официальный профиль VK не подтверждён, поэтому не подменён ссылкой на отдельный пост.
- Архив признаний содержит 17 Recognition, включая 13 разрешённых владельцем сканов; на главной четыре избранных. МФТИ и три результата отбора/награды/гранта не получают выдуманного скана. Отсутствие скана обозначается отдельно от содержания подтверждения.
- В `Work` используются отдельные `stage`, `workType`, `aliases`, `basedOn`, `components`, `year`, `edition` и `featuredOnHome`. Стадия: концепция, прототип, в производстве, реализовано. Доступность/репертуар хранятся отдельно.
- `HeroVisual` хранит ID медиа и типизированную цель (`Work` с опциональным `CaseEvent` либо `unmapped`), а не копии заголовка/подзаголовка. Для `unmapped` показывается причина отсутствия ссылки; release gate требует связать каждый кадр до выпуска.
- Сейчас в каталоге 23 работы (13 реализованных, 10 концептов/прототипов), две конфигурации, 15 программ и 43 кейса. На главной шесть избранных реализованных работ; полный каталог и хронология находятся в своих разделах.
- Для hero подготовлены пять локальных веб-фрагментов и постеров из пользовательских источников. Исходники остаются вне репозитория; владелец разрешил показ выбранных медиа 2026-10-05 (`rights: cleared`). Прототип с Еленой Ковылиной исключён из hero главной. Шестой указанный ролик пока не найден.

## Golem Data Base и MindDB

Прямого клиента/API-связи с Golem Data Base или MindDB в браузере нет. Команда `npm run stats:golem -- <path-to-event_registry.json>` готовит обезличенный агрегат из read-only реестра. Текущий снимок Golem от 2026-08-31 содержит 55 папок событий: 30 со связанными источниками, 13 с неоднозначными связями и 12 изолированных. Это единица архивной инвентаризации, не количество подтверждённых публичных показов. 43 записи CaseEvent сохраняют участия и контексты; статистика считает только состоявшиеся события по категориям, отдельно от формы участия.

Для hero подготовлен локальный агрегированный снимок MindDB на 2026-08-30 из каталога сессий и QC-проверки длительности: 150 сессий, 1 751 тейк, длительность измерена для 1 348 видео и суммирована примерно в 69,8 часа. В сайт не переносились строки отдельных тейков, участники или исходные отчёты.

Это редакционный снимок, а не живая интеграция; `publication` и `privacyReview` остаются `review`. PUBLICATION-SCOPE-01 реализован: агрегат отложен в publication-plan.ts и отсутствует в публичном блоке и данных. Если он включён в пакет, gate требует оба одобрения; простое отключение проверки при оставшемся показе не допускается. Распределение тета/альфа/бета/гамма не рассчитано по утверждённой методике и не отображается как данные. Для будущего обновления нужны владелец источника, повторяемый экспорт, определения метрик, проверка согласий и приватности, дата актуальности и поведение при устаревшем снимке. Браузер не подключается к частной базе.

## Рекомендуемое развитие CMS

Следующий небольшой шаг — вынести карточки из `site.ts` в отдельные проверяемые файлы данных (например, Astro Content Collections с общей схемой), оставив рендеринг статическим. Это улучшит редактирование и ревью, не добавляя серверную базу.

Графические связи и ссылки на provenance останутся явными ID-ссылками и будут проверяться при сборке. Вопрос о веб-панели решать отдельно: она нужна только если определены редакторы, права, согласование и удобный процесс хранения изменений в Git. Не подключать Golem как CMS без подтверждения, что он должен быть источником публичного контента.

## Общие правила выборки и проверок

`src/data/site.ts` хранит редакционный корпус. `src/data/publication-plan.ts` фиксирует версию и явные ID кандидатов первого пакета; наличие ID не изменяет publication. `src/lib/publication-scope.ts` проверяет выбранные записи, разрешения и зависимости, ограничивает поля публичной проекции и собирает allowlist файлов. `src/data/catalogue.ts` предоставляет одинаковую выборку для компонентов, маршрутов, статистики и gate. Подробные внутренние локаторы остаются в редакционном корпусе; в публичной проекции source содержит только URL, остальные локаторы убираются. Стадия не определяет доступность заказа.

`npm run dev` показывает весь редакционный каталог с заметкой предпросмотра и noindex, включая ещё не принятые документы и статистику. Это локальная рабочая среда; её нельзя использовать как публичный хостинг. Дизайн-стенд и редакционный каталог подключаются интеграцией только в dev из `src/views/DesignSystem.astro` и `src/views/EditorialWorkspace.astro`. `npm run build` формирует только публичную проекцию: неопубликованные Work/Case не создают HTML/routes/sitemap, недоступные документы и MindDB исключаются, физические файлы public/ проходят allowlist. `scripts/verify-build.mjs` проверяет и фактическое отсутствие исключённых файлов, и отсутствие внутренних локаторов в HTML/JSON/JS. Старый `?id`, прежний `/formats/` и неизвестная страница используют общий `LegacyNotice`: предупреждение, ручная ссылка и переход на главную соответствующего языка через пять секунд. Публичной таблицы соответствий ID нет; внутренний resolver остаётся инструментом учёта источников, а не маршрутизацией сайта.

Скрипты читают доверенные TypeScript-модули через scripts/site-data.mjs; build сверяет канонические пути с routes.ts без фиксированного числа страниц. content:check проверяет редакционный корпус. Release gate проверяет выбранный пакет, зависимости, права и конфигурацию аналитики; build проверяет физический allowlist и отсутствие внутренних локаторов. В текущем артефакте 102 канонические локализованные страницы и два noindex-входа /formats/, подготовленные Work доступны. Полнота миграции не выводится из успешной сборки или release gate: расширенный содержательный перенос завершён на 100% по бэклогу 2026-10-10; реальная доставка аналитики и итоговый аудит подтверждены. Отдельные проходы по слоям и M6 остаются следующей работой. Старые URL сняты с условий выпуска решением владельца 2026-10-07.


## Образование и параметры участия

Образование содержит 15 Programme. `additional-programmes.ts` дополняет исходный корпус и уточняет его по первичным Obsidian-источникам. `modules` используют EditorialSections, `authorIds` — опубликованные профили Person. `documented` означает содержательное описание в источнике; проведение устанавливается через CaseEvent. ## Подготовка изображений, PDF и текстовых копий

Решение владельца от 7 октября 2026: документы показываются как изображения, большие фотографии получают сжатые версии, текстовые копии связаны с источником и страницами. Общий конвейер — `npm run media:prepare`; полный read-only архив — `node scripts/prepare-media.mjs --archive`. Подготовка требует Python 3.11+, зависимостей `scripts/media-requirements.txt`; `ODA_MEDIA_PYTHON` задаёт другой интерпретатор. Обычная сборка использует проверенные файлы из Git и не требует Python/OCR.

Исходник не изменяется. SHA-256 исходника + версия политики + параметры + версии библиотек определяют кеш. Фотографии: длинная сторона до 2000 px, WebP quality 82–74, ориентир 350 КБ; страницы/схемы/афиши: до 2600 px, quality 88–84, ориентир 900 КБ. Пропорции, ориентация EXIF и полный кадр сохраняются. Нижняя граница качества важнее произвольного лимита байтов; превышение явно записано как `withinBudget: false`. Небольшие исходные PDF могут быть легче страниц WebP: единообразие просмотра не означает уменьшение каждого файла.

Служебный `.local-server/media-cache/index.json` связывает источник, его хеш, страницу, размеры/хеш изображения, текстовый файл и статус извлечения. Тексты каждой страницы и объединённая копия остаются в приватном кеше. PDF без текстового слоя используют Tesseract RU+EN при наличии движка и моделей; иначе получают `needs-ocr`. OCR имеет отдельный кеш по хешам движка и моделей, поэтому его изменение не пересоздаёт изображения. Машинный текст отмечен `machineTextNeedsReview`; страницы без читаемого текста явно отмечены, пустые файлы не объявляются распознанными.

Tesseract берётся из PATH или `ODA_MEDIA_TESSERACT`, модели — из `ODA_MEDIA_TESSDATA` либо `.local-server/media-tools/tessdata` (`eng.traineddata`, `rus.traineddata`). Модели доступны в [официальном tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast); обычный запуск не скачивает зависимости и не отправляет документы во внешние сервисы.

`src/data/prepared-media.ts` — генерируемый внутренний реестр производных, а не новый редакционный источник. Публикуются только изображения типизированных записей с разрешёнными правами; подготовка архива сама не меняет публикационный статус. Публичная проекция удаляет хеши/внутренние пути, включает страницы только вместе с разрешённым документом и владельцем. `DocumentList` использует MediaGallery/MediaFigure/общий просмотрщик; оригинальный PDF остаётся дополнительной явно подписанной ссылкой. Текст не публикуется автоматически: цены, переписка и персональные данные требуют редакционного отбора.

`content:check` проверяет оригиналы и производные, устаревание, количество страниц, соответствие галереи реестру. `python -X utf8 tests/prepare-media.test.py` проверяет повторное использование кеша, восстановление испорченного результата, изменение источника/политики/OCR, ориентацию и сохранность оригинала.

Архивные изображения определены в `archive-media.ts`: это визуально проверенная подборка с явными связями Work/Case/образовательного обзора, а не автоматический импорт parent-графа V1. `archiveSource` содержит исходный путь, SHA-256 и исходные ID; `originalAccess: internal` исключает подготовительные оригиналы из dist. В браузер попадают производные и редакционные подписи, а внутреннее происхождение остаётся в исходных данных/inventory. Повторы и обложки используют существующий Media ID. Сканы наград/писем рассматриваются отдельно как документы.

Образовательный обзор имеет собственную подборку `media`; общие учебные кадры с неизвестной датой не присваиваются произвольной программе или датированному событию. Работа сохраняет первое изображение для обложки; остальные — MediaGallery. Подробный Case аналогично показывает обложку и галерею; краткий CaseRow использует плитки для нескольких кадров. `screenshot` означает кадр интерфейса, сохраняет полный кадр и имеет собственную подпись в WorkCard.

## Локальная редакционная среда — 2026-10-10

Корневой start-local-v2.cmd напрямую вызывает scripts/start-local.mjs через Node. Node-запуск проверяет identity обоих локальных серверов, останавливает только процессы этого проекта и поднимает DEV 5177 и PUBLIC 5178 с PUBLIC_ANALYTICS_ENABLED=false. CMD показывает результат короткого запуска; сами серверы работают скрыто в фоне. PowerShell/WScript и перечисление процессов через CIM не используются. Служебные endpoints доступны только на loopback; чужие Host/Origin отклоняются.

PUBLIC обслуживает проверенный статический артефакт, созданный обычными astro build + verify-build в отдельной .local-server/public-builds/ директории (ODA_BUILD_DIR). Изменения src/scripts/public/config запускают пересборку. Артефакт активируется только после проверки и отсутствия изменений источников во время сборки; при ошибке/пересборке остаётся предыдущая версия. Панель показывает состояние, время сборки и необходимость обновить уже открытую страницу. Локальный сервер вставляет панель в HTTP-ответ; файлы артефакта, обычный dist и sitemap её не содержат. Сама панель имеет одну реализацию scripts/editorial-client.js. Неопубликованный маршрут переключается в явно названный каталог, а не изображает наличие страницы в PUBLIC.

DevNote помечает служебный текст как DEV · не публикуется; DevPublicationMark отдельно отмечает записи вне публичного состава по publicRecordIds. Карточки Work/Programme/Case/Recognition и MediaFigure используют общий механизм. buildPublicRecordIds добавляет виртуальные ID изображений страниц только для документов из проверенной публичной проекции; исключённый документ не делает свои страницы публичными. Производная страница наследует статус документа и не помечается DEV лишь из-за отсутствия отдельной записи Media. Реальная стадия концепта и условия участия остаются публичными полями. Комментарий не скрывается CSS: DevNote не рендерится в production. verify-build проверяет отсутствие редакционных markers/endpoints, каталога и внутренних локаторов во всех HTML/JS/JSON.

/editorial/ читает docs/EDITORIAL-REGISTER.yaml на сервере: фильтры по сущности, языку, статусу и названию, абсолютные счётчики, блоки/вопросы/решения и переходы на сайт. Копии статусов в клиенте не редактируются и не являются вторым хранилищем; после изменения реестра каталог перечитывается обновлением страницы. Валидатор scripts/editorial-register.mjs не допускает verified без полного разбора, согласования, применённого коммита и закрытых вопросов. Статус принятия текста независим от включения в publicationPlan. Руководство процесса — EDITORIAL-PLAN.md.
