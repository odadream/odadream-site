## Индексация: факты до обновления

- Уведомление найдено в другом уже авторизованном Gmail: письмо Google Search Console от 26.10 «Новые причины препятствуют индексированию страниц с сайта odadream.art». Перечислены переадресации, noindex, alternate canonical и soft 404.
- В интерфейсе Search Console (данные на 23.10): 138 страниц проиндексированы, 22 исключены. Единственный soft 404 — устаревший `/?id=for-events`: по принятому контракту V1 он показывает LegacyNotice и возвращает на главную. Возвращать этот адрес в индекс или объявлять его исправленным не следует. Ещё 12 текущих страниц просканированы, но пока не включены Google в индекс; HTTP- и HTML-проверки не обнаружили их технической блокировки.
- Через существующий read-only доступ Search Console подтверждено индексирование `/ru/`, `/en/` и `/ru/works/mindshow/`; canonical Google совпадает с нашим.
- Карта `sitemap.xml` прочитана 23.10, ошибок и предупреждений нет. Поле `indexed` ответа sitemap API не используется как счётчик индексации.
- `/ru/recognition/` и страница фестиваля Циолковского имеют состояние «URL is unknown to Google». Это отсутствие подтверждённого обхода, а не доказательство блокировки кодом.
- Старый `/ru/works/theatre-of-my-name/` исключён по noindex; его canonical ведёт в образование. Это ожидаемая перенесённая страница, её не следует возвращать в sitemap ради устранения предупреждения.
- API инспекции корня вернул 500; этот ответ API не выдаётся за HTTP 500 самого сайта.
- Независимый HTTP-обход всех 184 canonical URL из публичной карты подтвердил HTTP 200, правильный canonical и отсутствие noindex. На 16 RU/EN страницах обнаружен видеофайл в `og:image`.
- Точные примеры остальных исключений из интерфейса: noindex — `/en/works/journey-to-yourself/` и `/ru/works/theatre-of-my-name/`; alternate canonical — `/index.html`; переадресации — HTTP и WWW варианты домена. Это ожидаемые исключения, а не запрет индексации актуального каталога.

## Проверка и публикация

Сначала проверяются изменённые библиотеки, публичная проекция, типы и зависимости; затем свежая сборка и затронутые браузерные сценарии. Один полный release-контроль выполняется в CI. При ошибках сохраняется baseline и повторяются причины/зависимости, а не все уже пройденные матрицы.

Результат доставки и SHA артефакта фиксируются после успешного workflow в RELEASE-RUNBOOK. Отсутствие ошибок в HTML не гарантирует немедленного включения каждой страницы в выдачу: последующий обход и выбор Google остаются внешним процессом. API grant Search Console read-only; дополнительно доступен уже авторизованный интерфейс владельца. Повторная отправка sitemap выполняется после проверки опубликованной версии.

Исходная независимая копия: `%LOCALAPPDATA%/ODA.dream/site-v2-backups/2026-10-26T22-16-54-397Z-76fa372d`, HEAD `60b82a8`, 1996 файлов. Подробные HTTP/API/npm отчёты остаются в игнорируемой `.local-server/seo-review-27/`, без токенов в репозитории.

## Дальнейшее упрощение

PageView всё ещё большой dispatcher, а site.ts объединяет типы и несколько исторических слоёв данных. Их разделение уже описано в MAINTENANCE-AUDIT и backlog; полная перестройка в этом выпуске не нужна. Новые линтеры не добавлялись ради дублирования TypeScript/Prettier/design:check: вместо этого усилены проверяемые контракты фактического HTML и состояния редактора.

Дополнительный структурный обход свежего HTML: у всех 184 страниц ровно один H1, нет страниц без входящих внутренних ссылок (минимум два других адреса). Совпадения международных названий между RU/EN допустимы. Название технологии и одноимённой работы совпадает в title; дальнейшая редакторская дифференциация этих названий полезна, но не является установленной причиной исключения из индекса.
