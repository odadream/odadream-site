# План миграции ODA.dream V1 → V2

Дата анализа: 5 октября 2026. Статус: на согласовании; новые редакционные решения и очередность ниже — предложения. Уже принятые решения владельца сохраняют силу. Миграция и публикация в этой задаче не выполнялись.

Цель: отобрать полезное для задач V2 содержание, переработать его в актуальную структуру и стиль, сохранив необходимые связи и совместимость входов. Готовность определяется качеством согласованного смыслового пакета.

**Правило отбора:** содержательная оценка в приложении ниже имеет приоритет над трактовкой полного переноса. 238 ID — реестр исходников и старых входов. Оценка: 57 текстовых источников, 51 справочная запись, 36 доказательств, 34 медиа-записи, 28 событий/серий, 15 заглушек, 9 навигационных записей, 8 служебных. Эти числа не являются количеством будущих страниц.

### Различия источников

- 13 ID отсутствуют в опубликованном архиве: это дополнительные записи организаций. Их нельзя выдавать за уже опубликованные страницы или приравнивать к потерянным работам.
- В рабочем корпусе 239 файлов на 238 ID: `event-pleinair-metro-2024` встречается дважды с одинаковым содержимым. Переносить сущность один раз, сохранив источник дубля в аудите.
- `media-theatre-my-name-photos` отличается от редакционного архива. Использовать актуальный рабочий текст после проверки diff.
- Старый `works.yaml` называет игру «Парадокс Победы», Markdown — «Парадокс Успеха». Решение владельца закрепляет «Парадокс Успеха»; импорт YAML не должен вернуть старое название.
- Даты `updated` и даты событий не подменяют год создания работы. В V2 год сейчас установлен у колец; остальные восемь записей имеют явный `null`.
- Публичные показы, репертуар и доступность заказа проверяются отдельно. Старое рекламное определение «touring» нельзя автоматически преобразовать в `bookable`.

## 3. Что сохраняем и что преобразуем

| Содержание V1 | Назначение в V2 | Правило миграции |
|---|---|---|
| Большие формы, перформансы, инсталляции, Материя | Work, подборки и связи с сериями | Один канонический ID работы; тип, стадия, состав и доступность отдельно |
| Концепты и лаборатории | Подборка R&D в «Работах» | На главную не попадают; стадия и характер изображения явно подписаны |
| Лекции, мастер-классы, практики, игровые предложения | Format / образовательные программы; конкретные проведения — CaseEvent | Не превращать каждую версию программы в самостоятельное произведение |
| Нейромандала, OS, MultiSync, движки | Страница технологии и при необходимости подробные страницы методов | Сохранить содержательные объяснения и источники; избежать копий одного текста в нескольких работах |
| События и серии | CaseEvent и группировка по серии | Связи Work–Case–Organization–Evidence; серия не увеличивает число состоявшихся показов |
| Документы, награды, благодарности, публикации | Evidence / Recognition / источники | Указаны издатель, дата, предмет подтверждения и привязка; одинаковый скан не считается дважды |
| Команда, биография, CV | Studio / People / связанные свидетельства | Не потерять авторство отдельных работ; организации и люди имеют разные роли |
| Институции, бизнес, образование | Cooperation / Format | Сохранить разные сценарии обращения и условия сотрудничества |
| Галереи, записи, PDF, аудио, внешние видео | Media, связанные галереи и документы | Для каждого типа нужен явный способ просмотра/загрузки и понятная ссылка при отказе внешнего сервиса |
| Hub и Lotus-порядок | Навигация, подборки, связи | Сначала проверить текст hub; затем объединить навигацию. Не переносить граф React как движок V2 |
| Debug/служебные записи, скрытые контакты | Внутренний архив / закрытая редакционная информация | Решение фиксируется по записи; скрытость не снимается импортом |

Матрица функций:

| Функция | Состояние / действие |
|---|---|
| RU/EN, переход языка, back/forward | Есть в V2; сохранить в тестах для каждой новой страницы |
| Lightbox изображения, видео-постеры, клавиатура, темы | Есть; использовать общие компоненты |
| Галереи, аудио, PDF, внешние embed | В V1 есть ссылки/обработка; в V2 общего полноценного покрытия пока нет. Сначала инвентаризация, затем минимальные необходимые компоненты |
| Wiki-links, `media:id`, контактные токены | Разобрать при импорте в ID-связи/Media/общие CTA. В готовом HTML не должно остаться сырых токенов |
| Аналитика GA/Метрика и согласие | Модуль есть в рабочей V1, в V2 не найден. Перенести согласованные события и настройки; факт включения аналитики на текущем публичном сайте отдельно проверить |
| Lotus, процедурные фоны, настройки его панелей | Не входят в утверждённую архитектуру V2; сохраняются в архиве |
| Golem/MindDB | Источники read-only с provenance и датой снимка. Публичный браузер не получает доступ к частной базе |

## 4. Последовательность работ

### M0 — зафиксировать границы и приоритеты, P0

**Результат:** исходники и файлы с хешами; отдельные списки опубликованного содержания и поздних дополнений. Назначить владельца редакционной сверки, технического исполнения и итоговой приёмки. Роли могут выполнять одни и те же люди.

**Приёмка:** для каждого из 238 ID есть источник, категория, текущее направление и очередь. Из аналитики/Search Console, если доступны, получить входные URL и наиболее посещаемые страницы. Без этих данных приоритет предварительный, популярность не выдумывать.

**Уже сделано:** полный метаданный инвентарь и сравнение трёх корпусов в этой задаче. Решения `proposedAction` ещё требуют редакционной сверки содержания.

### M1 — подготовить схему и выбранный смысловой пакет, P1

**Результат:** единая схема полей, матрица источников выбранного пакета и предлагаемые редакционные изменения. Сплошной импорт не является целью.

- По мере роста выбранных данных рекомендуется хранить сущности отдельными файлами/коллекциями Astro с общей проверкой вместо разрастания `site.ts`. Это не предварительное условие первого редакционного пакета. Сохранить текущие ID и функции получения данных; панели администратора и серверной БД для миграции не требуется.
- Добавить источники к фактам, авторские/организационные роли, alias, series, `basedOn`, даты и неизвестные значения. Длинный рассказ/метод/история должны иметь место в модели, а не теряться при сокращении до карточки.
- Исправить противоречия до импорта: старый status `production/rnd/patent` не переносится механически в WorkStage или доступность.
- Подготовить конвертер `---RU---`, wiki-links, медиа-токенов и контактных CTA. HTML/Markdown сверяется человеком; не выполнять произвольный код исходной записи.

**Приёмка:** пробный пакет — реализованная работа, концепт/прототип, событие, документ, организация, длинный метод. Все связи разрешаются; обе локали заполнены; повторный импорт не создаёт дубликаты и не перезаписывает принятые решения владельца.

Для hero-кадров Нейромандалы/«Культурного кода» уточнить целевую сущность. Если это метод или программа, рекомендую расширить HeroVisual соответствующим типом цели, сохранив текущие Work-связи, вместо создания фиктивной работы ради снятия unmapped.

### M2 — перенести художественный корпус, P1

**Очередь A:** проверить глубину девяти существующих страниц. Следующие кандидаты оцениваются по добавляемой ценности: «Театр Имени Меня», «Воронка», «Мама и Малыш», «4-е измерение», «Счастье». Подготовить 2–3 наиболее полезных кандидата с материалами; все пять не становятся обязательными новыми страницами. Основание выбора приведено в разделе «Содержательная оценка и отбор».

**Очередь B:** «Маяк», «Момент Даршана», «Другие люди», «Нейродоска почёта», «Потусторонний» — выборочные кандидаты подборки R&D после проверки актуальных стадий и релевантности. Полный перенос всех концепций не требуется.

**Очередь C:** «Культурный нейрокод», «Взлом мозга», «Путешествие», образовательные программы и технологии — после решения, что является Work, Programme, Format или Method. Дополнения из Golem проходят проверку идентичности; версии и алиасы не размножают работы.

**Приёмка каждой работы:** каноническое имя, RU/EN, тип и стадия, краткое описание и сохранённый содержательный рассказ, авторы/роль студии, медиа, доступность либо явно неизвестное состояние, связи с показами, источники. Документированный год или `null`. Главная остаётся выборкой реализованных работ.

### M3 — восстановить историю, подтверждения и роли, P1

**Результат:** расширенная хронология из уникальных проведений, архив признаний и согласованные сущности людей/организаций.

- Использовать проведённую оценку event-записей; переносить отобранные вехи и контексты работ из M2. Краткие события могут оставаться строками хронологии, а не отдельными кейсами.
- Выбрать из 36 proof-записей документы для конкретных утверждений и сценариев доверия; сопоставить их с прежним списком и записями V2, избегая дублей. Полная публикация всех коротких proof-страниц не нужна.
- Сохранить кейсы Портала, Дикой Мяты, ЦИПР и другие подтверждённые контексты по источникам. Заявки, отказы и намерения остаются отдельными фактами.
- Для отобранного пакета извлечь из справочников необходимые организации/соавторов и проверить их роли. Самостоятельные страницы всех организаций и контактов не требуются.

**Приёмка:** событие имеет дату/место/роль и связанные работы; документ подтверждает конкретный факт; статистика считает те же сущности, что и список. Для неизвестного авторства/даты есть редакционная задача, а не декоративная подстановка.

### M4 — медиа и совместимость URL, P0 для выпуска

**Результат:** файл или осознанное решение для каждого старого публичного входа и ресурса.

- Расширить `audit-media.mjs` за пределы `/images/content/`: PDF, M4V, другие каталоги и значимые внешние ссылки. Процедурные SVG Lotus можно оставить в архиве, но входные ссылки на них сначала учесть.
- По умолчанию рекомендую сохранять старые публичные пути содержательных медиа, если файл подходит и показ разрешён. Разрешение владельца на работы/частные заказы уже записано; повторная общая проверка прав на те же материалы не нужна.
- Отдельно решить документы третьих лиц, персональные исходники и временные/закрытые ссылки. Разрешение показа работы не означает выгрузку приватного каталога участников MindDB.
- Новые версии изображений оптимизировать; исторические оригинальные URL сохранить либо дать проверенный HTTP redirect. Наличие нового превью по другому адресу не сохраняет старый URL автоматически.
- Для каждого ID: `exact-page`, `merged-section`, `archive-page` или мотивированное исключение. `/legacy/unavailable/` допустим как честный временный статус, но не критерий завершённого переноса значимых публичных страниц.
- Сохранить `?id`, `lang`, `internal=true`, старые aliases и парные RU/EN-страницы. Новую canonical-страницу не менять из-за алиаса.
- На GitHub Pages текущий root bridge — JavaScript-переход, не HTTP 301. Для query-based 301 и индивидуальных redirects нужен отдельный HTTP-слой; решение принимается по объёму входного трафика и потребностям SEO.

**Приёмка:** полный manifest старых входов проверен автоматически и выборочно в браузере; старые PDF/изображения скачиваются либо имеют проверенный redirect; неизвестные ID не ведут молча на главную. Не утверждать, что 215 старых страниц перенесены, только потому что fallback отвечает.

### M5 — измеримость и проверка качества, P0

**Результат:** воспроизводимая проверка итогового сайта и основных действий посетителя.

- Перенести согласованные page_view, почту/контакт, внешние ссылки, материалы и просмотр медиа в аналитику V2. Проверить согласие и отсутствие двойного счёта: запрос старого ID не должен превращаться в две конверсии.
- Проверить `/ru/`, `/en/`, каждую работу/кейс и все migrated ID; язык, история браузера, клавиатура, focus-return, отказ загрузки картинки/видео/PDF.
- Матрица: 390/601/797/1440/1920 px, обе темы, RU/EN; карточки и паспорта без наложений и горизонтального overflow.
- `npm run format:check`, `npm test`, `npm run content:check`, `npm run check`, `npm run build`, `npm run test:e2e`, `npm run release:check`.
- Заменить фиксированное ожидаемое число страниц в `verify-build.mjs` на число из реестра маршрутов; иначе расширение каталога потребует ручных поправок.
- Повторить Lighthouse на production build. Старые оценки 99/100 относятся к сентябрьскому baseline, не к текущей версии. Собрать новый отчёт; лабораторный TBT не выдавать за полевой INP.

**Приёмка:** проверки проходят, число HTML-страниц соответствует реестру, sitemap/канонические URL/hreflang согласованы, тяжёлые медиа имеют постер/размеры и не загружаются все одновременно. События аналитики наблюдаются на тестовом окружении.

### M6 — переключение и наблюдение, P0

**До разрешения владельца:** подготовить конкретный проверенный артефакт, manifest, список принятых редакционных решений и отчёт release gate. Публичный домен и `main` не менять.

**После явного запроса на выпуск:** выполнить workflow V2 на `main`, проверить его завершение и доступность домена. Текущий workflow ветки только проверяет и сохраняет артефакт; deployment workflow активируется на `main` и выполняет release gate.

**Откат:** перед выпуском сохранить идентификатор последнего реально опубликованного workflow/artifact, commit/tag и копию текущей конфигурации Pages. Единица работы — смысловой модуль или сущность, связанная с задачей посетителя. Исходный файл сохраняет provenance; новая страница может использовать несколько источников, а один источник — дать сведения нескольким связанным сущностям.

|---|---|
| Большой рассказ о произведении | Краткая карточка + выверенный рассказ об опыте, истории и методе + паспорт + отобранные медиа |

| Галерея из отдельных media-узлов | Отобранная последовательность на странице работы/кейса с подписями |

Авторскую историю/метафору можно сохранить как авторскую; причинные, медицинские и количественные утверждения требуют своего основания. Перевод следует отредактированному смыслу, а не копирует ошибки и шум английской/русской версии.

### 5. Критерий отдельной страницы

Отдельная страница оправдана, когда одновременно есть самостоятельная сущность или сценарий посетителя, отличающееся содержимое, достаточные сведения/медиа и понятный путь входа. В остальных случаях — раздел существующей страницы, карточка, запись данных, связанное приложение или внутренний архив. Уникальный старый ID и большой объём текста этих условий не заменяют.

Нужен двухслойный учёт:

1. **Редакционный:** нужное содержание отобрано, объединено/переработано и проверено для V2. Готовность считается по согласованному пакету смыслов и сценариев.
2. **Совместимость:** каждый старый вход получил осмысленную судьбу. Это не требует публиковать его старую страницу. Временный fallback, переход к релевантному разделу и архивное решение различаются в manifest.

Отсутствие заглушки/служебной записи в V2 не считается потерей содержания. При этом полезные факты из её метаданных и внешние входы учитываются отдельно. Исключение из новой публичной структуры не означает удаление исходника или автоматический отказ от старого URL.
