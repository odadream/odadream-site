Сохранять общую `.git` на месте. Перенос выполняется средствами Git и копированием локальных рабочих ресурсов, а не заменой двух папок целиком.

1. Остановить только идентифицированные DEV/PUBLIC этого проекта; не трогать другие worktree/процессы.

## Публикация и контроль

1. Прямое решение владельца о выпуске должно относиться к конкретному проверенному head. Описание будущего сценария и проверка готовности сами по себе не считаются выполненной публикацией.
2. Перевести main на ветку выпуска через fast-forward; отправить обычный push в origin/main. Не применять force-push. CI ещё раз проверяет release и выкладывает именно проверенный dist.
3. Дождаться успешного Pages deployment. Проверить `/`, `/ru/`, `/en/`, работу, событие, образовательную программу, 404/старый `?id`, изображения и видео по HTTPS. Проверить DEV/редактор не доступны, SEO относится к V2, sitemap читается и HTTPS не перенаправляет циклически.
4. Проверить ноль запросов к аналитике до согласия; после согласия — новые GA4/Метрика, page_view и контрольные действия без дублей; после отзыва — остановка отправки. Наблюдать ошибки и данные после выпуска, учитывая задержку отчётов.
5. Внешние Search Console/Вебмастер: подтвердить обновление sitemap и отсутствие критических ошибок обхода. Сохранить URL CI/deployment, опубликованный SHA и фактическую дату выпуска в задаче.

## Восстановление

Причины восстановления: неуспешная доставка артефакта, неработающие основные страницы/ресурсы, утечка DEV или приватных материалов, некорректное согласие/отправка аналитики, неверные canonical/domain.

Не переписывать историю. Восстановить дерево опубликованного V1 из `archive/published-site-v1.2.2` отдельным новым коммитом поверх main либо повторно доставить проверенный архивный Pages artifact. Прежние VITE_* variables позволяют восстановить аналитику V1. Проверить домен/HTTPS и контрольные страницы повторно. Локальные изменения V1 возвращать из записанного stash/снимка только в отдельном архивном checkout; не накладывать их на Astro V2.

Первичные инструкции GitHub: [custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [custom domain](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).
