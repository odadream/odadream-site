# ODA.dream V2 working rules

This branch is a clean Astro static site, not the Lotus CMS. Do not copy the old React graph, 238 legacy Markdown records or generated SVG nodes into this tree. The old sources remain read-only under the archive tag and local backup.

Keep the V5 visual grammar: warm near-black, restrained green signal, JetBrains Mono for reading, Manrope for headings, disciplined spacing and lines, material before interface. The canonical tokens are in `src/styles/tokens.css`; do not add ad-hoc inline styles.

The profile contract is in `docs/DESIGN-TOKENS.md`: profile inputs → semantic roles → components. Use `--signal-*` for both navigation and page accents, `--grid-*` for page/specimen grids, and `TechnicalMark` for technical symbols. Statistics use `RecordStamp tone="reference"`, not a raised document panel. Filled Manrope 800 folios belong only to the background.

Before adding or changing presentation patterns, read `docs/DESIGN-GUIDE.md`. It defines field semantics for every content type, the distinction between positional codes and stable IDs, and the functional use of marginal notes, vertical position codes, folios, media registers and record stamps. Use the shared `SectionRail`, `StatisticsStamp`, `RecordStamp` and `MediaFigure` components and keep their live examples in `/design-system/` synchronized. Never invent technical data to fill a decorative field.

Content is bilingual in `src/data/site.ts`. Keep work, work configuration, educational programme, case/event, evidence, person, organization and media roles distinct. Every public assertion needs a source; `production` never means bookable. R&D and archival status must be explicit. Do not call outreach contacts partners. Media access is not a usage license; all copied images remain under rights review until approved.

Treat `docs/SITE-PRINCIPLES.md` as the approved information-architecture and homepage contract. Treat `docs/PROJECT-BACKLOG.yaml` as the canonical machine-readable task list. When an accepted decision changes page purpose, section order, content model or scope, update both documents in the same change. Update backlog status/acceptance when work progresses; do not record speculative decisions as approved rules. `docs/CONTENT-AND-CMS.md` describes the current data layer and integrations; keep it factual as architecture changes.

Owner decision 2026-10-07: old V1 IDs/URLs do not require exact redirects. Root ?id, old /formats/ and 404 show the shared bilingual LegacyNotice and return home after 5 seconds. Preserve language, never grant access through internal=true, and exclude notice routes from sitemap. The 238-ID manifest is internal source inventory only, not public runtime routing. Validate new canonical routes, links and anchors.

Update the specific localized entry in `src/data/lastmod.json` when page content materially changes; do not replace it with a build timestamp.

For local iteration/commits use `npm run verify`: it includes staged/unstaged/untracked changes, allows narrow checks only for known components, and expands shared/unmapped changes to full. Use `--since REF` for committed changes; `--files` adds scope and never hides actual changes. Markdown/backlog-only edits validate metadata. Run `npm run verify:full` before general review/integration even if quick passed. `npm run verify:release` builds/tests the same artifact, then checks rights and analytics. `npm run test:e2e` also prepares a fresh build. Do not run raw Playwright against unchecked dist or an unidentified DEV server. Run one verification at a time. Scoped reports do not prove migration completion, owner acceptance or permission to publish. The V2 verify workflow uploads an artifact only. Do not push, create a PR, switch the domain or alter `main` without explicit owner approval.

Start task context with `npm run task -- TASK-ID` and README's source-of-truth map. Current statuses live in PROJECT-BACKLOG.yaml; historical plans/audits are read on demand. Read relevant contract sections rather than the whole inventory. Update the task and affected contract, plus SITE-PRINCIPLES for an accepted product change; detailed run logs stay in ignored verification artifacts.
